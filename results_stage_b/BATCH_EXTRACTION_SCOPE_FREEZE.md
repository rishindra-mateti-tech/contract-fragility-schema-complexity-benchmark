## 1. Executive Protocol and Execution Boundaries

This document records the exact baseline state and operational scope boundaries for the Stage B Batch Extraction Candidate Pipeline. This block builds a deterministic, fail-closed batch extraction engine that generates quarantined reviewable extraction candidates for eligible, monomorphic Stage B operations from the frozen candidate manifest.

- Zero LLM calls, provider API requests, live HTTP wire traffic, mock-execution runs, mutation operators, or empirical benchmark evaluations are authorized.
- Stage A artifacts, frozen protocols, raw pinned specifications, and historical pilot artifacts remain completely untouched.
- Existing pilot slots (`SLOT_GITHUB_01`, `SLOT_STRIPE_02`) are excluded from this batch and preserved in `data_stage_b/canonical/`.
- Polymorphic union slots (`SLOT_STRIPE_03` / `PostRefunds`) are excluded from monomorphic batch extraction.
- No artifact generated by this pipeline is labeled `CANONICAL_FAITHFUL`.
- All successfully generated batch candidates are assigned lifecycle status `EXTRACTED_PENDING_HUMAN_VALIDATION` under creation mode `BATCH_GENERATED_CANDIDATE`.
- No independent validation is claimed or inferred from author actions.

## 6. Preflight Rejection Policy (Fail-Closed Rule)

An operation will not be extracted if any preflight check fails:
- Raw source artifact missing or corrupted (SHA-256 or Git blob SHA mismatch).
- Operation JSON pointer fails to resolve.
- Source format is non-spec code (Python, TypeScript AST) requiring code extraction.
- Source contains external file references (`FEAT_REF_EXTERNAL_FILE`) or remote references (`FEAT_REF_REMOTE_URL`).
- Source contains unratified polymorphic unions (`FEAT_COMP_ONEOF`, `FEAT_COMP_ANYOF`).
- Source contains binary or multipart formats (`FEAT_BIN_FORMAT_BINARY`, `FEAT_CT_MULTIPART_FORM_DATA`).
- Schema recursion depth exceeds limit of 5 (`FEAT_REC_EXCESSIVE_DEPTH`).
- Operation requires custom/manual logic not defined in generic rules.

For every failed preflight check, the engine emits a deterministic rejection record documenting the exact slot ID, operation ID, failure reason, pointer, and evidence, and safely proceeds to the next candidate.
